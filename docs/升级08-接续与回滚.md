# 升级08 · 接续与回滚（改造09 → v0.8.0）

> 面向：**装插件的人**。本文只讲三件事：怎么装、怎么验、怎么退。
> 实现细节见 `docs/CONTRACT-升级09-Boss体验.md` §8 与 `src/api.js` 的 `upgradeMigrate`。

---

## 0. 这次升级的承诺（Boss 需求 9）

> **升级不丢任何既有任务、证据、阶段、历史。**

这不是口号，是下面这几条机制撑起来的：

| 风险 | 机制 | 位置 |
|---|---|---|
| 旧数据缺新字段 → 报错 | 一律**读时给默认值**，绝不抛 | `src/board.js` `normalizeLegacyTask()` |
| 迁移把 `rev`/`id` 改掉 → 前端与后端对不上 | 迁移**只往事件里补一个字段**，其余一字不动；**绝不重写整个 board 文件** | `src/api.js` `upgradeMigrate` |
| 迁移写一半就崩 → 数据半残 | **先备份**，备份失败则一个字节都不动 | `src/store.js` `backupState()` |
| 迁移失败 → 无法回退 | 备份目录 + `restoreState()` | 本文 §3 |
| 迁移跑两次 → 重复改动 | 幂等：版本已到位 ⇒ 不重写；phase 行按「是否已有」判定 | `src/store.js` `migrate()` |

### 为什么不能「重写整个 board 文件」

`board.jsonl` 是 **CAS 幂等键与 `rev` 语义的真相源**。整体覆盖重写的话，
只要漏一个字段，任务的 `rev` 就会和前端手里的对不上 ——
Boss 需求 9「任务原样存活」当场破功，而且**症状是隐性的**（页面能打开，
只是任务状态悄悄回退）。所以这里必须逐条合并。

## 1. 装（沿用 `install.sh`）

```bash
cd /home/ubuntu/output2026/butlers/dev/cs-bots

# ① 打包（profile 是通过 file: tgz 引用的，见 §1.1）
npm pack            # → cs-bots-0.8.0.tgz

# ② 安装 + 自检（一条命令）
bash install.sh

# 或指定通道/profile
bash install.sh --channel git --ref v0.8.0
bash install.sh --profile web
```

### 1.1 退出码（**必须看懂**）

| 退出码 | 含义 | 怎么办 |
|---|---|---|
| `0` | 装好**且自检通过** | 继续 §2 |
| `1` | 安装失败 | 看输出；多半是网络/npm 通道问题 |
| `2` | **装上去但自检不通过** —— 最危险 | 见下方「为什么危险」 |

**为什么 `2` 最危险**：DSH 遇到 `link:` 断链 / bundle 没进
`dsh.profile.bundles` / 版本错位时，**只打一行 `skipping profile bundle` 就静默跳过** ——
页面照常 HTTP 200，功能全失效。「页面能打开」≠「插件装好了」。
所以 `install.sh` 用 `--dump-config` 验证**装配树里真有我们的行**。

### 1.2 只自检（不动任何东西）

```bash
bash install.sh --check-only
dsh --profile web --dump-config | grep -n 'cs-bots'   # 必须能搜到
```

### 1.3 profile 引用方式

```
/home/ubuntu/.dsh/profiles/web/package.json
  "cs-bots": "file:/home/ubuntu/output2026/butlers/dev/cs-bots/cs-bots-0.7.2.tgz"
```

> 升级时这个 tgz 文件名会随版本变（`0.7.2` → `0.8.0`）。
> `install.sh` 负责改引用；手工装的话记得同步这行。
> bundle 列表里必须有 `cs-bots`（第 25 行附近）。

```jsonc
  "targetVersion": 2,          // 本次要到的版本
  "counts": { "tasks": 36, "longrun": 12, "phaseRows": 8, "notes": 200, "wakes": 48,

              "把 board 事件流 schema 版本记到 2（现有任务 rev/id/字段原样保留）" ],
  "risks": [ "无阻塞风险（迁移前仍会自动整目录备份）" ],
```

```bash

# → 记下来；跑完 preflight 再 stat 一次，数字必须一模一样
```

### 第 2 步：迁移 —— 幂等、先备份

```bash
curl -s -X POST http://127.0.0.1:PORT/cs-bots/api/upgrade/migrate
```

```jsonc
{
  "ok": true,
  "backupPath": "/home/ubuntu/.dsh/cs-bots.bak-2026-11-10T22-30-00-123Z-upgrade09",
  "bossTouched": { "updated": 3, "skipped": 33 },
  "phases": { "backfilled": 1, "tasks": [ "t-35" ] },
  "schema": { "ok": true, "migrated": true, "version": 2 },
  "replayed": null
}
```

**迁移做三件事**（详见契约 §8.2）：

1. 旧任务补 `bossTouched` —— 凡 `createdBy` / `mandate.sender` / 历史 `byId`
   是 Boss 的 ⇒ `true`。**只改这一个字段。**
2. 「已完成 + 有 longrun + 没有任何 phase 行」的任务 ⇒ 按 `task.artifacts`
   生成一条末阶段产物 `{ kind:'phase', index: phases.length-1, state:'done' }`，
   让已完成的长任务也有阶段产物可看。
   **这是唯一的「推断写入」**，`note` 里写明 `升级迁移：按总产出物回填`。
3. **已存在的 phase 行不动**。

**幂等验证**（重要）：

```bash
# 跑两次，第二次必须 updated=0 / backfilled=0
curl -s -X POST .../upgrade/migrate | grep -o '"updated": [0-9]*'
curl -s -X POST .../upgrade/migrate | grep -o '"backfilled": [0-9]*'
# → 第二次都应为 0
```

## 3. 退（两种粒度）

### 3.1 完整回滚：整目录恢复

`backupState` 的备份是**整目录快照**，所以回滚就是「把目录换回去」：

```bash
# ① 先确认备份目录存在且非空
ls -la /home/ubuntu/.dsh/cs-bots.bak-*/upgrade09

# ② 用 store.js 的恢复原语（confirm:true 是硬要求）
node --input-type=module -e '
  import { restoreState } from "/home/ubuntu/output2026/butlers/dev/cs-bots/src/store.js"
  const r = restoreState("/home/ubuntu/.dsh/cs-bots", "/home/ubuntu/.dsh/cs-bots.bak-XXXXXX-upgrade09", { confirm: true })
  console.log(r)   // { ok:true, path: "/home/ubuntu/.dsh/cs-bots" }
'

# ③ 再回退插件本体
cd /home/ubuntu/output2026/butlers/dev/cs-bots && git checkout v0.7.5 -- .
bash install.sh
```

> `restoreState` 会把**当前目录**改名为 `.pre-restore-<时间戳>` 再覆盖，
> 所以回滚本身也是可再回退的（`...bak-*` 与 `...pre-restore-*` 都在）。

### 3.2 只回滚数据、不动插件

迁移只补 `bossTouched` 和 phase 行，两者都是**加法**。
如果只想撤销这两处：

```bash
# 备份里 task-meta.jsonl 的 phase 行是迁移前的；board.jsonl 的 bossTouched 同理
diff <(grep '"kind":"phase"' /home/ubuntu/.dsh/cs-bots.bak-*/upgrade09/task-meta.jsonl | sort) \
     <(grep '"kind":"phase"' /home/ubuntu/.dsh/cs-bots/task-meta.jsonl | sort)
# → 空输出 = 没有新增；非空 = 删掉新增的行即可
```

### 3.3 迁移失败怎么办

**迁移失败不会留下半残数据**：备份失败 ⇒ 直接中止、一个字节都不动
（返回 `UPGRADE_BACKUP_FAILED`）；中间出错 ⇒ 备份目录还在，按 §3.1 恢复。

```jsonc
// 失败时的真实返回
{ "ok": false, "reason": "迁移中止：备份失败（…）——未写入任何改动", "code": "UPGRADE_BACKUP_FAILED" }
```

## 4. 常见坑

| 现象 | 原因 | 处理 |
|---|---|---|
| 页面 200 但插件功能全没 | bundle 没进 profile（DSH 静默跳过） | `bash install.sh --check-only`，看退出码是不是 2 |
| 迁移后任务状态回退 | 有人在迁移时重写了 board 文件 | 见 §0「为什么不能重写整个 board 文件」；用 §3.1 回滚 |
| 迁移跑了两次，phase 行多了 | 没走 `/upgrade/migrate` 而是手工写 | 契约要求幂等，用端点跑；真出错用 §3.2 |
| `preflight` 说 `willDo` 有东西但不想动 | 正常 —— 那正是「升级接续」要做的事 | 先 §2 第 1 步核对 `risks`，再决定是否迁移 |
| 装完页面没变化 | 需要重启 DSH | `systemctl restart dsh-web.service`（**会中断在途会话**，先确认） |

## 5. 上线演练（**已实测，可复现**）

上面 §1–§3 是操作手册。这一节是**已经在真实数据副本上跑过的结果**——
不是「应该能行」，是「跑过了长这样」。

### 5.1 包本身是否可用

```bash
npm pack                                  # → cs-bots-0.8.0.tgz (598 kB, 57 files)
mkdir -p /tmp/pkg-verify && cd /tmp/pkg-verify && tar xzf …/cs-bots-0.8.0.tgz
cp -r <repo>/test package/ && cd package && bash test/run-all.sh
# → ✅ 全部通过（exit 0）   1242 / 1242
```

**为什么这一步不能省**：源码目录能跑通，不等于**打出来的包**能跑通
（`files` 字段漏一个目录、`.npmignore` 误伤、`exports` 没指到新文件 —— 都会让包静默残缺）。
在包里跑一遍全量套件，是唯一能证明「这个 tgz 是完整的」的办法。

数据来自当时的 `~/.dsh/cs-bots/` 副本（144 条 board 事件、2 个任务）。

**预检是只读的**（前后指纹对比，证明一个字节都没写）：

```
task-meta.jsonl  ✅ 未动  {"size":4503,   "mtimeMs":1794326787407.48}
```

1. **包可用**：解包 + 全量套件 1242/1242，说明 `files` 没漏、`exports` 没断。
2. **接续成立**：真实数据上迁移后 `rev`/`id`/`status`/`subject` 零漂移，且可重复执行。

## 6. 一句话总结

> **装用 `install.sh`（退出码 0 才算装好）→ 验用 preflight/migrate 三步 →
> 退用 `restoreState`。**
> 全程**先备份、逐条合并、绝不重写 board 文件**，
> 所以 Boss 的需求 9「任务原样存活」是有机制保证的，不是口头承诺。
