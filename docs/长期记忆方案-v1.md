# cs-bots 长期记忆方案 v1（Bot 新建任务 / 跨会话交接 / 上下文防膨胀）

> 日期：2026-11-05（Asia/Shanghai）
> 问题：Bot 在单一对话里反复推进任务，上下文越来越长，最终超限，任务流畅性被打断。
> 目标：让「任务」脱离「单一对话」，落到分层记忆 + 任务笔记，任何 Bot/会话都能接手，上下文按需召回而非全量常驻。

## 1. 根因定位

| 症状 | 根因 | 证据 |
|---|---|---|
| 单对话上下文超长 | 任务的全部讨论都留在同一条会话消息流里，每轮全量重放 | client.js 消息流无摘要 |
| 换会话就忘 | 任务状态只在 board.jsonl 里，讨论细节在旧会话，无结构化抽取 | src/board.js 只有事件流 |
| L4 任务笔记无人用 | L4 设计上「按需 recall」，但没有任务 id → L4 的绑定机制 | src/memory.js 无 taskId 字段 |
| 上下文注入无预算 | `contextFor` 有 tokenBudget，但任务笔记没进 L4 召回路径 | memory.js:2144 |

## 2. 方案：任务笔记（L4 task note）绑定 board task

### 2.1 数据模型
- 新增 `src/tasknote.js`（或扩展 memory.js 加 `addTaskNote`）：
  - `taskId`：关联 board 任务 id
  - `layer: 'L4'`
  - `content`：本轮/本步的决策、结论、下一步
  - `rev`：CAS 版本（防并发覆盖）
  - `cwd`：任务工作目录（L4 本就按 cwd 隔离）
  - `phase`：`plan | doing | block | done`
  - `tags`：`['task:<id>']` 便于检索

### 2.2 写入时机（Bot 侧纪律）
1. 每次 claim 任务后，写一条 `phase=plan` 笔记：目标 + 计划步骤
2. 每完成一个子步骤，写一条 `phase=doing` 笔记：结果 + 剩余
3. 遇到阻塞，写 `phase=block` 笔记：阻塞原因 + 需要谁/什么
4. 完成前写 `phase=done` 笔记：验收结果 + 可复用经验

### 2.3 召回路径（避免常驻膨胀）
- L4 **不进入 `contextFor` 常驻注入**（现有设计，保持）。
- 提供 `bot_memory_search(query, layers:['L4'], cwd)` 按需召回。
- 提供新的 `bot_task_notes(taskId)` 工具：按 taskId 拉取该任务的全部 L4 笔记（倒序，限 20 条）。
- 接手任务时：先 `bot_task_get` 看任务 → 再 `bot_task_notes(taskId)` 看历史笔记 → 再开工。

### 2.4 上下文预算纪律
- 每个 Bot 会话启动时，只注入 `contextFor(layers:['L0','L1','L2','L3'], cwd, tokenBudget: <window/4>)`。
- 任务细节不进常驻；需要时用 search/notes 按需取。
- 单任务笔记上限：每条 ≤ 600 码点（memory.add 自动切分）；单任务笔记总数上限 50，超出按 `phase=done` 优先归档。

## 3. 跨会话交接流程（lead → worker → reviewer）

```
1. lead 创建任务（bot_task_create）
2. lead 写 L4 plan 笔记（bot_memory_add layer=L4, tags=['task:<id>'], content=计划）
3. lead claim + wake worker（bot_wake reason=task-assigned, taskId）
4. worker 收到 → bot_task_notes(taskId) 读计划 → 开工
5. worker 每步写 L4 doing 笔记
6. worker complete（bot_task_update action=complete, artifacts=[...]）
7. reviewer 读 artifacts + L4 done 笔记 → 验收
8. 不通过 → bot_task_update reopen + 写 L4 block 笔记
```

## 4. 防止「单一对话上下文超长」的三条硬规则

1. **任务不落地不接新活**：claim 前必须写 plan 笔记；没有 plan 笔记的任务视为未就绪。
2. **会话不背任务史**：每轮结束前，把本轮关键结论写 L4 笔记；下轮从笔记 + board 恢复，不依赖旧消息。
3. **长会话自动降级**：当单会话消息数 > N（建议 40 条）或 token 估算 > 窗口 60%，提示 lead 把剩余工作拆新任务 + 新会话，旧会话只保留笔记。

## 6. 验收

- `memory.add({layer:'L4', taskId, content})` 返回 entry 带 taskId
- `memory.notesForTask(taskId)` 返回该任务全部 L4 笔记，倒序
- `bot_task_notes` 工具在无 memory 服务时返回可读失败
- 跨会话：worker 会话能仅凭 notes + board 恢复任务，不读旧会话消息
- 笔记总数超上限时按 done 优先归档，不静默丢弃

## 7. 风险

- L4 笔记写太多也会膨胀 → 用上限 + 归档控制
- taskId 与 board 任务生命周期不一致（任务删除后笔记残留）→ notesForTask 对已删除任务仍返回笔记（保留证据），但标记 `task:deleted`
- 零依赖纪律：不引第三方，纯用现有 memory.js 能力
