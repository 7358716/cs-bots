## 一、这版修了什么（对应你的截图）

| 你的现象 | 根因 | 本版处理 |
|---|---|---|
| 图 1：导入报「校核失败：请求体过大（>2MB）」 | 后端写死 `MAX_BODY=2MB`（`api.js`），前端却允许选 600MB 文件 —— 两个上限互相矛盾，334KB 的包都进不去 | 只给 `/transfer/inspect`、`/transfer/import` 放宽到 **800MB**（base64 后约 1.34 倍余量）；其余端点仍守 2MB，防 DoS。超限时返回 **413 + `BODY_TOO_LARGE` + 可读提示**，不再伪装成「校核失败」 |
| 图 2：提示「导入后会改到 `C:\...\.dsh\cs-bots/**<部门>/<名字>**」 | `transfer.js` 用字符串拼 `'/'`，Win 上混出反斜杠+正斜杠 | 全部改走 `displayPath()`，按本机分隔符输出；确认页新增「**本机落点**」一行 |
| 图 3：导入后 **一个 Bot 都没带入** | `applyImport` 的 bots 分支**只产出 plan，从未调用 `roster.create`** —— 日志写「已加 N 个」，注册表 0 个 | 导入真正落地：走与「建 Bot」**完全同一条路径**（`department` → 派生 cwd），并按本机主目录重算；逐条上报 新增/覆盖/跳过/改名/**失败原因** |
| 图 3/4：左树只有 `misc/ops/qa/dev` 四个空文件夹，**没有 cs-bots 主目录，也没有三级** | 三级登记逻辑只藏在「整理工作区」一个按钮里；建 Bot / 换部门 / 导入**都不登记** | 新增域服务 `ws-hierarchy.js`，建 Bot、导入、换部门三条路径**自动登记三级**；另给「检查左侧栏层级」「重建分组」两个按钮 + `GET /workspaces/hierarchy` |

## 二、新增能力

### 1. 三级工作区（主目录 → 部门 → Bot）

- 顺序固定 `主目录 → 部门 → Bot`，**逐级 await、全局串行锁**（2026-11-15 `domain inconsistent` 事故的教训写进了实现）。
- 建之前**先读 `workspace.json`** 判重（内存态在域初始化期不可靠），**先 mkdir 再 create**（Win 首次安装坑）。
- **只建分组，不挂会话**（挂会话由宿主负责）。
- 失败**降级不抛**：拿不到 `workspaceRegistry` 时目录照样建，界面给出「稍后点重建分组」。
- **retired 的 Bot：目录保留、分组不建**（你的第 3 条）。

### 2. 建 Bot 当场回显三段状态

建完立刻显示：`✅ 主目录分组  ✅ 部门分组  ✅ Bot 分组` + 目录路径 + 「左侧栏刷新后可见三级」。
哪一步没成，当场看到原因，不用去左侧栏猜。

### 3. 导入的三种同名策略真正生效

`覆盖` = 更新档案、**保留原 id 与会话**（不重建，不丢上下文）；`跳过` = 不动本机；`自动改名` = 新建 `名字_2`。

## 三、跨平台路径纪律（ADR-002）

新增 `src/paths-cross.js`，所有路径相关判断收口到一处：

| 规则 | 为什么 |
|---|---|
| 拼接一律 `node:path` | 手拼 `'/'` 在 Win 上必错（你截图里就是） |
| 展示一律 `displayPath()` | 给人看的路径必须按本机分隔符 |
| 比较一律 `isInside()/pathsEqual()` | 盘符大小写、`\` 与 `/` 混写必须认成同一目录（旧 `startsWith` 在 Win 上永远 false） |
| 目录名一律 `safeSegment()/checkSegment()` | **汉字放行**（你的第 1 条）；拦截 Win 保留名 `CON/PRN/AUX/NUL/COM1-9/LPT1-9`、非法字符 `: * ? " < > |`、结尾点/空格；NFC 归一（macOS NFD 兼容）；超长截断 |

**CI 机械检查（新增检查 6）**：禁止在模板串里手拼目录分隔符。这条现在会让构建失败，防止回退。

## 四、怎么验证（请在 Win 上跑这一段）

```bat
:: 1) 在解压后的插件目录里跑跨平台回归（不依赖测试框架）
node test\win-regress.mjs

:: 预期最后一行：RESULT: PASS (30/30)
```

然后在页面上按这个顺序验：

1. **建 Bot**：「Bot 档案 → 新建 Bot」，部门选「＋ 新增部门…」建一个中文部门（如 `测试部门1`），建 Bot。
   → 应看到三段 `✅`；左侧栏出现 `cs-bots → 测试部门1 → <Bot 名>`。
2. **导入**：点「导入」，选 Linux 那边的 zip。
   → 不再报「请求体过大」；确认页有「本机落点」一行；导入完成后逐条列出「新增/覆盖/失败及原因」。
3. **左侧栏层级**：点「检查左侧栏层级」→ 有缺口就点「重建分组」（幂等，连点不会重复）。
4. **三级确认**：`%USERPROFILE%\.dsh\cs-bots\<部门>\<Bot 名>` 目录存在；左侧栏 `cs-bots` 展开是 `部门 → Bot`。

## 六、已知限制

- `workspace.json` 的登记**只增不删**：孤儿分组需要手动在宿主里删（避免误删让 Bot 看起来消失）。
- 导入「自动改名」不会跟着改 Bot 目录名以外的引用（技能目录按 Bot 名分区，会一起改名）。
- 部门 id 目前仍建议英文；**显示名可以是汉字**（你已确认），汉字 id 也已支持。
