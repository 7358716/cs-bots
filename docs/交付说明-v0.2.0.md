## 一、这一版回答了你问的那个问题

> **「待办和便签为什么单列 UI，是仿照记忆进化吗？和任务的关系是什么。」**

**是，也不是。** 事实经过：v2 补齐「记忆进化」的对等能力时，把**能力对等**
误当成了**页面也对等**——memory-evolve 有独立页面，这边就也各开一个页签，
于是页签从 7 涨到 11。这是**越界**，不是设计。

**原架构的页签只有两种**：
1. **协作对象**（任务 / Bot / 房间）——你有多个、有生命周期、要点进去看详情；
2. **配置资产**（技能库 / 工作流库 / 设置）——配一次、被多处引用。

待办、便签、纪律、提示词**两类都不属于**：它们是既有对象的视图或属性。

**与任务的关系**：三者是一条**漏斗**——
便签（想到就记）→ 待办（决定要做）→ 任务（决定交给谁做）。

## 二、做了什么

### 1. 页签从 11 收敛回 7（与原架构一致）

| 页签 | 子视图 | 一句人话 |
|---|---|---|
| 任务 | 协作看板 / 我的待办 / 便签 | 要做的活 |
| Bot | — | 谁来做 |
| 房间 | — | 在哪商量 |
| 记忆 | 事实与偏好 / 纪律与要求 / 提示词 | AI 该知道什么 |
| 技能库 | — | 怎么做 |
| 工作流库 | — | 按什么步骤做 |
| 设置 | — | 平台怎么跑 |

### 2. 不只是搬位置：补了「漏斗收口」
待办条目新增按钮 **「派下去」** → `POST /todos/promote`：
把待办变成协作看板上的正式任务（第一行做标题、全文做描述、截止日转 dueAt），
并把待办标成"进行中"，避免被重复安排。**幂等**（`sourceSeq=todo:<id>`，连点两次只出一个任务）。

### 3. 记忆补上真删除（原来只有归档）
- `remove` 现在诚实地叫**软删除**：进归档区、显示「已删除（可恢复）」、可恢复；
- 新增 `purge`（**彻底删除**）：内存 + 快照 + 重启后都不存在，不可恢复；
  事件流只留一条 `after:null` 墓碑记录"谁在何时删了什么"，审计不丢、内容不留。
- 归档区里删过的条目会明确标注，并给「彻底删除」按钮（强确认 + 后果说明）。

### 4. UI 补齐（人类视角）
技能来源目录管理、提示词分类管理、记忆自审间隔设置、Bot 档案「从记忆库导入」、
项目记忆切换与「归到当前项目」。

## 五、以后新增功能的判据（写进架构文档，防止再长回去）

> 新能力若**没有独立生命周期**、**不需要多人/多 Bot 共同引用**、
> **不产生可点进去的详情** —— 就**不许新开页签**，只能做既有页签内的子视图。
