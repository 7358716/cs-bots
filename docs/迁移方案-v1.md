# cs-bots 存量任务迁移方案 v1

> 日期：2026-11-05（Asia/Shanghai）
> 适用：把老会话/旧 Bot/旧任务板的数据迁移到 cs-bots 0.4.0+。

## 1. 数据源识别

| 老数据 | 位置 | 形态 |
|---|---|---|
| 旧任务板（agent-team） | `~/.dsh/storages/agent-team/boards/*.json` | JSON，字段 subject/status/owner/rev |
| 旧 Bot 注册 | `~/.dsh/storages/agent-team/members/*.json` | JSON |
| 旧房间 | `~/.dsh/storages/agent-team/rooms/*.json` | JSON |
| 旧记忆 | `~/.dsh/memories/projects/<cwd>/KEY.md` | Markdown 条目 |
| 旧便签 | `~/.dsh/storages/scratch/*.md` | Markdown |

cs-bots 新数据：`~/.dsh/storages/cs-bots/`（boards/rooms/roster/tasks），schema 见 `src/board.js` / `src/room.js` / `src/roster.js`。

## 2. 映射规则

### 任务（board）
- `subject` → `subject`（必填，空则跳过并记日志）
- `status` 映射：`todo`→`pending`，`doing`→`in_progress`，`done`→`completed`，`blocked`→`blocked`
- `owner` → `assignee`（若 roster 中存在同名 Bot，否则置 null 并记 orphan）
- `priority` 缺省 0；`labels` 缺省 []
- `rev` 不迁移，新板从 1 起新 rev
- 旧任务 id 加前缀 `legacy-` 避免冲突

### Bot（roster）
- `name` → `name`（重名加 `-legacy-N`）
- `cwd` 必须是绝对路径且不在 DSH_HOME 内；旧 cwd 无效则跳过并报错
- `label/instructions` 原样复制

### 房间
- `name`、`members`（按 session id 映射，找不到的成员丢弃并记日志）
- 旧消息**不迁移**（schema 差异大，仅保留房间壳）

### 记忆
- 不自动迁移条目；提供 `cs-bots memory import --from <old KEY.md>` 命令，按条目追加到新 KEY.md，带 `legacy:` 标签

## 3. 幂等

- 迁移脚本写入 `~/.dsh/storages/cs-bots/migration-log.jsonl`，记录 `{sourceId, targetId, ts, status}`。
- 重跑时：若 sourceId 已在 log 中且 targetId 仍存在 → 跳过；targetId 不存在 → 重新迁移。
- 提供 `--dry-run` 只输出将要迁移的条目，不写入。

## 4. 回滚

- 迁移前自动备份整个 `~/.dsh/storages/cs-bots/` 到 `~/.dsh/storages/cs-bots.bak-<ts>/`。
- 回滚命令：`cs-bots migrate rollback --ts <ts>`，恢复备份目录（先校验备份完整性）。
- 旧数据**永不删除**，迁移只读。

## 5. 验收

- 迁移后 `task list` 数量 = 老板数量（允许 orphan 被跳过，但必须在 log 中记录原因）
- 每个迁移任务 rev=1，status 映射正确
- 重跑迁移 log 显示全部 skip，无重复条目
- `--dry-run` 不改变任何文件（校验 mtime 不变）
- 回滚后 cs-bots 数据恢复到迁移前状态（diff 无差异）

## 6. 风险

- 旧 cwd 失效（单位/家里双机）→ 迁移时 Bot 跳过，需人工修正
- 旧消息不迁移 → 用户需知悉
- 旧 rev 丢失 → CAS 语义从 1 重新开始，不影响新操作
