# Step 01 · 原架构复原与信息架构（IA）诊断

> 存档目的：后续所有改动都以「原架构」为准绳。本文件锁定原架构的事实，以及
> 为什么会出现「待办/便签单列」这种越界，避免重复讨论。

## 1. 原架构（事实，来自 README + git 历史，不是回忆）

**领域层 = 5 个协作对象/服务**（`src/` 一一对应）：

| 域服务 | 文件 | 职责 | 持久化 |
|---|---|---|---|
| `board` 任务板 | `board.js` | 跨会话任务：依赖 DAG、CAS 状态机、验收 | `board.jsonl` + `.snap.json` |
| `roster` Bot 注册表 | `roster.js` | 持久 Bot，**独立 cwd = 写入边界** | `roster.jsonl` + `.snap.json` |
| `room` 房间群聊 | `room.js` | 消息流 + `seq` 游标 + 长正文旁路 | `rooms/<id>/log.jsonl` |
| `memory` 分层记忆 | `memory.js` | L0–L5、注入、检索 | `memory.jsonl` + FTS5 |
| `dispatcher` 唤醒桥 | `dispatcher.js` | 定向唤醒 + `dedupKey` 去重 | `wakes.jsonl` |

**页面层 = 7 个页签**（v0.1.1 之前）：

`任务` / `Bot` / `房间` / `记忆` / `技能库` / `工作流库` / `设置`

**页签与域的映射关系只有两种**：
1. **协作对象**（任务、Bot、房间）——你有多个、每个有生命周期、需要点进去看详情；
2. **配置资产**（技能库、工作流库、设置）——你配置一次、被多对象引用。

**三条原始设计原则**（README「设计要点」+ 代码注释）：
1. **独立工作目录**：持久 Bot 走 `ctx.agents.create({meta:{cwd}})`，因为官方
   `spawn_teammate` 无 `cwd` 字段、子会话强制继承父 cwd，而 cwd 同时是 fs 写入边界。
2. **自建而非寄生**：官方任务板 `TeamId=SessionId`（每会话一块）、roster 是
   flat immutable（无改名/删除/复用）⇒ 跨会话任务板与可维护 Bot 注册表必须自建。
3. **零第三方运行时依赖**：`test/ci-zero-dep.sh` 机械强制（5 项检查）。
   生态里任何插件（含 `dsh-memory-evolve`）都**不许 import**。

## 2. 越界是怎么发生的

v2 按 `ANALYSIS-memory-evolve-parity.md` 补齐「记忆进化」对等能力时，
**把"能力对等"误当成"页面也对等"**：memory-evolve 有独立页面，于是这边也各开一个页签。

结果页签从 **7 → 11**：

```
任务 · 待办 · Bot · 房间 · 纪律 · 记忆 · 便签 · 提示词 · 技能库 · 工作流库 · 设置
```

**这违反了原架构的第 1 条映射规则**：待办、便签、纪律、提示词都不是「有生命周期的协作对象」，
它们是**某个既有对象的属性/视图**：

- 待办 = 任务的**个人视图**（同一件事的两种粒度）；
- 便签 = 个人的**临时草稿**（不是对象，是一次性的）；
- 纪律 = AI 的**规矩**（和记忆同一心智：AI 该知道什么）；
- 提示词 = AI 的**指令模板**（同上）。

**判据（以后新增功能都用它自查）**：
> 新能力若没有独立生命周期、不需要多人/多 Bot 共同引用、不产生可点进去的详情，
> 就**不许新开页签**，只能作为既有页签内的子视图。

## 3. 结论：回到 7 个页签（不是新增，是归位）

| 主页签 | 子视图 | 归并为一句人话 |
|---|---|---|
| **任务** | 看板 / 我的待办 / 便签 | 「要做的活」 |
| **Bot** | （不变） | 「谁来做」 |
| **房间** | （不变） | 「在哪商量」 |
| **记忆** | 记忆 / 纪律 / 提示词 | 「AI 该知道什么」 |
| **技能库** | （不变） | 「怎么做」 |
| **工作流库** | （不变） | 「按什么步骤做」 |
| **设置** | （不变，新增自审间隔） | 「平台怎么跑」 |

页签数 **回到 7**，与 v0.1.1 原架构一致；新增能力全部落在子视图里。

## 4. 与「任务」的关系（用户直接问的那个问题）

不是同一件事，但**必须在同一个页面里**：

- `board` 任务：**协作单元**。有依赖 DAG、CAS 状态、验收人、可被 Bot 领取。跨会话可见。
- `todo` 待办：**个人备忘**。四轨（生活/工作/本项目/每日）+ 四象限 + 截止日。不参与协作。
- `scratch` 便签：**临时草稿**。一个文件，随手写，不整理。

关系是**漏斗的上游到下游**：便签（想到就记）→ 待办（决定要做）→ 任务（决定交给谁做）。
所以同页不同视图，并在待办条目上提供「升级为任务」的入口（后续增量）。
