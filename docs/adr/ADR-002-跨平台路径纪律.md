# ADR-002 · 跨平台路径纪律：路径决策集中到 `paths-cross.js`

- 状态：**已采纳**（0.20.0）
- 日期：2026-11-18
- 决策人：Boss（需求） + 开发管家（实现）
- 关联：`docs/DESIGN-0.20-三级工作区与建Bot闭环.md`、`docs/RELEASE-0.20.0.md`

---

## 背景

2026-11-18，Boss 在 **Windows 桌面版 DSH** 上报了四个故障，其中三个是同一个病：

1. 导入确认页显示 `…\.dsh\cs-bots/<部门>/<名字>` —— 反斜杠与正斜杠混用；
2. 导入后 Bot 一个都没带入 —— 「是否在本机主目录下」用 `cwd.startsWith(root)` 判断，
   Win 上盘符大小写/分隔符不同就永远返回 false，全部被当成「外来目录」；
3. 左侧栏只剩 `misc/ops/qa/dev` 四个空文件夹 —— 这些目录名本身来自「部门 id 直接当目录名」，
   而三级登记逻辑只在一个按钮里，从未被建 Bot/导入路径调用。

代码里还有第二类隐患：目录名清洗函数 `sanitizeDirSegment` 只考虑了路径穿越，
没有考虑 **Windows 保留设备名**（`CON`/`PRN`/`AUX`/`NUL`/`COM1-9`/`LPT1-9`）、
**Windows 非法字符**（`: * ? " < > |`）、**结尾点与空格**（Win 会静默丢弃），
也没有做 **Unicode NFC 归一**（macOS 导出的是 NFD，到 Win/Linux 会看起来一样、实际不同）。

## 决策

**所有与路径有关的三件事（拼、比、显）以及目录名清洗，统一收口到 `src/paths-cross.js`。**

| 关注点 | 唯一入口 | 禁止的做法 |
|---|---|---|
| 拼路径 | `node:path` 的 `join`/`resolve` | 模板串里手写 `/` 或 `\` |
| 比路径 | `isInside()` / `pathsEqual()` / `samePath()` | `a.startsWith(b)` |
| 显示路径 | `displayPath()` | 直接把内部路径丢给用户 |
| 目录名 | `safeSegment()`（洗）/ `checkSegment()`（判） | 各调用点自己 `.replace(/[\\/:*?"<>|]/g, '')` |

## 为什么不是「各模块各自处理一下」

- 这类缺陷**不会在本机复现**（Linux CI 全绿），只能靠纪律 + 机械检查发现；
- 2026-11-18 之前已经出现过两次同类问题（`isInsideDir` 的硬编码 `/`、`registry.create` 的 realpath 前置目录），
  说明「靠自觉」不成立。

## 强制手段

`test/ci-zero-dep.sh` **检查 6**：扫描 `src/`，凡是模板串里出现 `${...}/<` 这类手拼路径分隔符的写法，
构建直接失败。检查本身排除了 `paths-cross.js`（它就是处理分隔符的地方）与注释。

## 后果

- 代价：新增一个零依赖模块（~230 行）+ 18 条单元测试；所有调用点要改成新入口。
- 收益：Win/Linux 行为一致；`node test/win-regress.mjs` 能在目标机上自证（30 项）。
- 已知不做：不处理符号链接 realpath（那需要 IO，由调用方决定）；
  不把汉字转拼音（Boss 明确要求部门名可用汉字）。
