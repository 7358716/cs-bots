## 1. 一句话

**cs-bots 是一个跑在 DeepSeek Harness 上的多智能体协作平台。改造07 把它从「扁平的页签集合」升级为「分层架构」：上层是人类协作层，下层是 AI 基础设施层，两者通过穿透入口显式连接。**

## 3. 分层原则（为什么这样分）

### 3.1 上层调用下层，下层不反向调用上层

- 上层的 UI 组件通过 HTTP API 获取数据
- 下层的域服务通过 `tools.js` 暴露给模型
- 两者互不感知对方的内部结构

### 3.2 穿透是显式的，不是隐式的

- 正常页面只显示上层
- 下层通过顶部「⚙ 穿透」按钮显式进入
- 穿透面板是**只读 + 有限操作**，不暴露全部底层能力

### 3.3 保持「绝不静默失败」

- 所有模块的所有操作都有明确返回值
- 失败时返回人话 + 下一步建议
- 所有操作落盘，可审计

## 4. 功能归属：哪些进上层，哪些进下层

### 4.1 上层（人类协作层）—— 6 个页签

| 页签 | 包含功能 | 人类视角 |
|---|---|---|
| **工作台** | 任务看板、PDCA 复盘、待办、便签、成果 | 人建任务、看进度、验收 |
| **团队** | Bot 档案、团队列表、房间群聊 | 人管 Bot、看谁在干什么、进房间讨论 |
| **记忆** | 事实与偏好、纪律与要求、提示词 | 人看 AI 记住了什么、改 AI 的行为准则 |
| **技能库** | 技能、工作流 | 人看 AI 会什么、按什么步骤做 |
| **数据** | 文件浏览、PDCA 测量指标 | 人看数据、看效率 |
| **设置** | 平台参数、权限、安全 | 人配平台 |

### 4.2 下层（AI 基础设施层）—— 7 个区块

| 区块 | 包含功能 | 人类穿透后能做什么 |
|---|---|---|
| **注册表** | Bot 注册表、任务板事件流、团队注册 | 查看 Bot 生命周期、任务 CAS 历史 |
| **唤醒桥** | Dispatcher 队列、去重表、背压状态 | 查看唤醒日志、手动触发唤醒、强制 flush |
| **存储** | jsonl 事件流、快照、原子写、幂等集 | 查看存储健康、坏行统计、手动 replay |
| **路由** | 复杂度路由 T0-T3、免费/付费策略 | 查看路由规则、查看路由决策日志 |
| **验证** | 验收证据、退出码、测试结果 | 查看验收记录、手动重跑验收 |
| **建议** | 建议确认队列、纪律提议 | 采纳/驳回建议 |
| **订阅** | 任务订阅、房间扇出 | 查看订阅关系、订阅/取消订阅 |

## 5. 借鉴 Super-agent 的三项能力

改造07 从官方 Super-agent 原型（`deepseek-ai/dsh-superagent-prototype`，研究原型，非正式产品）借鉴了三项能力：

### 5.1 借鉴 3：Subscription 扇出（`src/subscription.js`）

- 任务可订阅房间，房间后续消息自动到达任务（作为上下文）
- **只加上下文，不改任务状态、不授予开工权力**
- 幂等：同一 (taskId, roomId) 重复订阅返回既有记录
- 滚动窗口：默认保留最近 20 条消息
- 实现：`src/subscription.js` + API 端点 + 3 个新工具

### 5.2 借鉴 4：工单阶段机（`src/stage.js`）

- 8 个执行阶段，自上而下首个命中
- 4 个 `person/*` 阶段需要人动手（强调色）
- 纯函数、无副作用、不落盘
- 实现：`src/stage.js` + API 附 `stageInfo` + 前端徽章

### 5.3 借鉴 5：prepare command（`src/roster.js` + `src/api.js`）

- Bot 可设开工准备命令（如 `git worktree add ...`）
- claim 前先跑，失败则不认领（绝不产生半成品）
- 安全边界：白名单 + execFile + 硬超时
- 实现：`roster.setPrepareCommand` + API 集成 + `runPrepareCommand`

## 6. 技术栈

| 层 | 技术 |
|---|---|
| 后端运行时 | Node.js ≥22.5，ESM，零第三方运行时依赖 |
| HTTP API | 宿主 `webServer.register`（前缀路由 `/cs-bots/api`） |
| 前端 | React 18，宿主模块加载器 `window.__ModuleLoader__.load` |
| 模型工具 | 宿主 `tools.register`，41 个 `bot_*` 工具 |
| 持久化 | JSONL 事件流 + 原子快照，SQLite 不引入 |
| 安全 | 会话鉴权围栏 + 同源校验 + 受保护区 + CSRF 防护 |

## 10. 设计原则（贯穿全部模块）

1. **绝不静默失败**：所有失败都有明确返回值 + 落盘证据
2. **事件流是真相源**：先落盘，再改内存，最后写快照
3. **CAS 优先**：任何变更都要带 `expectedRev`
4. **纯增量**：改造07 所有改动都是纯增量，不改动既有契约
5. **零第三方运行时依赖**：只用 node 内置 + 宿主包
6. **分层不隔层**：上层调用下层，下层不反向调用上层
