### 3.2 阶段徽章是什么意思

这是改造07 最重要的改进。以前你只知道任务「在进行中」，现在能看出**卡在谁身上**：

| 徽章 | 意思 | 你该做什么 |
|---|---|---|
| 🟠 **投递失败** | 消息发不到执行者 | 点穿透 → 唤醒桥 → 手动 flush |
| 🟠 **等你回答** | 执行者提了问题 | 打开任务详情回答问题 |
| 🟠 **等你验收** | 交付物做好了 | 打开任务详情验收 |
| 🟠 **受阻等你** | 执行者卡住了 | 打开任务详情看原因 |
| 🟠 **失败等你** | 执行者报错了 | 打开任务详情看错误 |
| ⚪ **排队中** | 还没人接活 | 派活给某个 Bot |
| ⚪ **空闲等触发** | 这轮干完了，等新消息 | 补充说明或等新触发 |
| ⚫ **正在干** | 执行者正在推进 | 不用管 |

**橙色 = 需要你动手**。看到橙色徽章，就点进去。

### 3.3 点开任务卡片

```
├────────────────────────────────────┤
│  谁建的    张三                     │
│  来源      人建的                   │
│  优先级    5（一般）                │
│  截止      2026-11-10               │
│  状态      [进行中]                 │
│  执行阶段  [等你验收] 需要你处理     │ ← 改造07

│  谁在做    Bot-A                    │
│  进度      ▓▓▓▓▓▓▓░░░ 70%          │
│  ...                                │
│                                     │
│  可以做什么                         │

└────────────────────────────────────┘
```

**「执行阶段」这一行是改造07 新加的**，鼠标停在徽章上会显示具体原因。

### 3.4 复盘周期（PDCA）

子页签「复盘周期」：

- 每个周期显示阶段进度条（planned → doing → checking → acting → done）
- **不许跳步**：想直接从 planned 到 done 会报错
- 复盘时可以记录教训，系统会提议把教训存进记忆（要你点「采纳」才生效）

### 3.5 我的待办

四轨待办：
- **生活**：家里的事
- **工作**：公司的事
- **项目**：本项目的事
- **每日**：今天必须做完的

每个待办可以标四象限（重要/紧急）。

### 3.6 便签

随手记。单文件原子写，不会丢。

### 3.7 成果

交付物列表，可以预览。文件可以点开看内容。


**点「档案」能看到**：
- 身份、经验、技能、预制记忆
- **准备命令**（改造07 新增）

### 4.2 准备命令怎么用（改造07 新增）

准备命令是「Bot 开工前先跑一遍的命令」。

**什么时候用**：
- Bot 需要 `git worktree` 建独立工作区
- Bot 需要先 `pnpm install` 装依赖
- Bot 需要先拉最新代码

**怎么设**：
1. 团队 → Bot 档案 → 点某个 Bot 的「档案」
2. 找到「准备命令」字段
3. 填命令，比如：`git worktree add ../my-task main`
4. 保存

**会发生什么**：
- 下次派活给这个 Bot 时，系统先跑这条命令
- 跑成功 → 任务正常认领
- 跑失败 → 任务**不会被认领**，返回错误原因
- 这样不会出现「认领了但环境没准备好」的半成品

**安全限制**（系统自动检查）：
- 命令第一个词必须是安全的：`bash` / `node` / `npm` / `pnpm` / `npx` / `git` / `ls` / `test` / `python3`
- 不能写 shell 语法（`&&`、`|`、`>` 都不行）
- 最多跑 10 分钟

## 9. 穿透面板（改造07 核心新功能）

### 9.1 什么时候该点「⚙ 穿透」

**平常不用点。** 只在下面这些情况点：

| 情况 | 进哪个区块 | 干什么 |
|---|---|---|
| 任务不动，怀疑没唤醒 | 唤醒桥 | 看唤醒日志，手动 flush |
| 怀疑数据坏了 | 存储 | 看文件健康，手动 replay |
| 想确认 Bot 注册对不对 | 注册表 | 看 Bot 生命周期 |
| 想确认路由走没走对 | 路由 | 看规则和决策日志 |
| 想确认验收证据 | 验证 | 看验收记录 |
| 想处理 AI 提的建议 | 建议 | 采纳/驳回 |

### 9.2 怎么用

1. 点右上角「⚙ 穿透」
2. 右侧滑出抽屉，显示 7 个区块：

```
┌────────────────────────────────────┐
│  底层工具                        × │
├────────────────────────────────────┤
│  ┌─ 注册表 ──────────────────────┐  │
│  │ Bot 注册表 / 任务板 / 团队注册  │  │
│  │ bots: 5  states: {...}         │  │
│  └───────────────────────────────┘  │
│  ┌─ 唤醒桥 ──────────────────────┐  │
│  │ total: 120 sent: 118 failed: 2 │  │
│  └───────────────────────────────┘  │
│  ┌─ 存储 ────────────────────────┐  │
│  │ files: 12 total: 14            │  │
│  └───────────────────────────────┘  │
│  ...                                │
└────────────────────────────────────┘
```

3. 点某个区块 → 展开详情
4. 有操作按钮的直接点（比如「强制投递队列」）

### 9.3 两个最常用的操作

**操作一：强制投递队列（唤醒桥）**

场景：任务显示「投递失败」，你确认会话是活的。

1. 穿透 → 唤醒桥 → 展开
2. 点「强制投递队列」
3. 看到「已强制投递：sent=N, failed=M」

**操作二：重建内存态（存储）**

场景：怀疑内存和磁盘不一致。

1. 穿透 → 存储 → 展开
2. 点「重建内存态（replay）」
3. 看到 replay 结果

⚠️ **replay 会重建内存态，正在跑的任务可能受影响**——用前确认没有重要任务在跑。

## 10. 任务订阅（改造07 新增）

### 10.1 这是什么

任务可以「订阅」一个房间，房间里的后续消息会**自动**到达这个任务——不用你每次都去 @ Bot 补一句「刚才房间说了什么」。

### 10.2 怎么订阅

1. 打开任务详情
2. 找到「订阅」区块
3. 选一个房间
4. 点「订阅」

### 10.3 订阅后会发生什么

- 房间里有人说话，任务自动收到（作为上下文）
- **不会改变任务状态**
- **不会打扰执行者**（默认不唤醒）
- 每个任务最多保留最近 20 条上下文

### 10.4 怎么取消

任务详情 → 订阅区块 → 点订阅记录旁的「取消」。

⚠️ 取消是终态，不能恢复，需要的话重新订阅。

## 11. 常见场景快查

### 场景 1：任务卡住了

```
1. 看卡片阶段徽章是什么
2. 橙色 → 点进去，按徽章含义处理（见 3.2 表）
3. 灰色「排队中」→ 派活
4. 还是不动 → 穿透 → 唤醒桥 → 强制投递
```

### 场景 2：Bot 派活了但没反应

```
1. 穿透 → 唤醒桥 → 看日志
2. 如果 failed 且原因是 agent-not-live：
   - 团队 → Bot 档案 → 点「启动会话」
   - 或穿透 → 注册表 → 重启全部 Bot 会话
3. 再派一次活
```

### 场景 3：想看看 AI 记住了什么

```
记忆 → 事实与偏好 → 按层看
```

### 场景 4：想让 AI 开工前先准备环境

```
团队 → Bot 档案 → 档案 → 准备命令 → 填命令 → 保存
```

### 场景 5：讨论里说的东西希望相关任务知道

```
1. 打开任务详情
2. 订阅区块 → 选讨论所在房间 → 订阅
3. 之后房间里说的话，任务自动收到
```

### 场景 6：怀疑数据有问题

```
穿透 → 存储 → 看文件列表和大小
→ 有问题就点「重建内存态（replay）」
```

## 13. 常见问题

**Q：为什么只剩 6 个页签了？**
A：改造07 做了分层。所有功能还在，只是重新归组了。

**Q：以前的链接还能用吗？**
A：能。旧页签 id 会自动映射到新页签。

**Q：阶段徽章和状态徽章有什么区别？**
A：状态是「任务还在不在做」（5 个值），阶段是「卡在谁身上」（8 个值，更细）。

**Q：订阅会打扰执行者吗？**
A：默认不会。上下文到达不等于要打扰，除非你显式要求唤醒。

**Q：准备命令失败会怎样？**
A：任务不会被认领，你会看到失败原因。修好命令再派一次即可。

**Q：穿透面板能改数据吗？**
A：只能做有限操作（flush、replay）。不能直接改数据——那是危险的。

**Q：手机上能用吗？**
A：能。页签横向滚动，穿透面板是全屏抽屉。

## 改造08 · 需求 1–5（2026-11-09）

> 这一节的每一条都对应你原话里的一条要求，写完当天就上了线（0.7.2 已部署重启，启动图校验 PASS）。

### 需求1 · 任务页只展示人建的任务，智能体任务单独一页

| | 改前 | 改后 |
|---|---|---|
| 「我的任务」页 | 人和智能体的任务混在一起 | 只显示 `source=human`（你自建的任务） |
| 智能体任务 | 混在同一个列表里翻 | 单独的「智能体任务」页签，按状态分类 |

- 后端 `GET /tasks?source=human|ai` 早已支持（`src/board.js` 里 `source` 字段），这次是**前端把它用起来**。
- 「我的任务」页保留「只看需要我处理的」开关；「智能体任务」页不显示这个开关（智能体的活不需要你逐条盯）。

### 需求2 · 派活后能追踪进度、看到产出物、看到对话

这一条挖到了一个**真 bug**，不是你操作的问题：

> `eventsToMessages` 只读 `ev.content`，而官方会话事件是 `{ type, seq, time, data }`，
> 内容在 `data.content` / `data.message.content` 里；`tool/call`、`tool/result` 是顶层事件。
> 结果：**对任何真实会话都恒定返回 0 条** —— 所以你看到的就是「没有对话内容可看」。

实测同一个真实会话（4795 个事件）：

| | 修前 | 修后 |
|---|---|---|
| 对话片段总数 | **0** | **2625** |
| 你的发言 | 0 | 110 |
| 执行者正文 | 0 | 74 |
| 思维链 | 0 | 465 |
| 工具调用 | 0 | 1306 |
| 工具结果 | 0 | 670 |

新增/变更：

- 后端 `GET /tasks/conversation?id=&limit=` —— 只读打开执行者会话（`persistence.open(id,'read')`，不抢所有权），返回 `{ bot, sessionId, messages[], total, truncated, available }`。
- 前端任务详情新增**任务对话**面板：显示执行者身份、消息条数；默认只给正文（手机不被思维链淹没），点「看全部」才展开工具调用与思维链；「去对话」直接打开它的会话，宿主不支持就复制会话 ID 兜底。
- 无执行者时是**空态**（「还没有执行者」+ 下一步），不是报错。
- 产出物空态改成说清「为什么现在没有」：未完成时正常；已完成却没带证据时提示可以重开补交。

### 需求3 · 团队页只显示你建的团队，负责人有标识，成员可选

- 团队页只拉 `GET /teams?type=big`（后端 `type` 字段保留不动，只是 UI 不再暴露「大小团队」概念）。
- 负责人带 `👑 负责人` 标识，成员列表里负责人加 `👑 ` 前缀；移出负责人会明确警告「移出后团队将没有负责人」。
- 建团队时负责人用下拉选择，成员用勾选组（可多选，支持新建 Bot 后再来选）。
- 「看房间」→ 跳房间页并**按团队名定向筛选**：房间页顶部出现「筛选房间：包含「X」→ N 个房间」和「✕ 清筛选」。
- 你要的「穿透房间看子团队工作内容」：房间页本来就是超级管理员视角，所有房间都能进、都能看长正文（`withBody=1` 一次取回），筛选只是在大列表里做定向。

### 需求4 · PDCA 人机分治（这条改动最大）

你的原话：「pdca 是对用户长任务进行复盘跟进的，人类主导；智能体的 pdca 流程你优化一下」。

结论是**两种周期，两套纪律**：

| | `kind=human`（你的） | `kind=agent`（智能体的） |
|---|---|---|
| 谁主导 | **你** | 智能体自己 |
| 用途 | 跟长任务、防漂移 | 定期批量归纳、自我提升 |
| 阶段纪律 | 计划→执行→检查→改进→完成，**五步不可跳** | 复盘可**一次性提交**，提交即自动闭环 |
| UI 位置 | 「📋 我的任务周期」（主区） | 「🤖 智能体归纳周期」（折叠在下方） |
| 复盘后 | 留在「改进」等你显式推进到完成 | 自动 → 完成（`autoClosed: true`） |
| 产出 | 经验教训 + 标准化建议 | 同左，但**只进建议队列**，你采纳才落库 |

为什么 agent 允许一次性提交：让它假装走 `planned→doing` 是对事实的虚构。你要的是「结论 + 可采纳的标准」，不是看它表演流程。

**「定期」怎么落地**：`reviewer` 只做被动回合计数（每回合 +1，到阈值就 `due`），它不自己起定时器（宿主生命周期不可控）。所以：

1. 周期页读 `GET /review/status`，把到期会话列出来（当前线上实测 3 个会话到期，共 111 回合）；
2. 你点「让它归纳」→ `POST /review/urge` 唤醒它，并给它明确三步指令（开 `kind=agent` 周期 → 一次性复盘 → 建议进队列）；
3. 归纳出的纪律**不会自动改自己**，走 `bot_suggestion_propose`，你采纳才生效。

这条暗道是被故意堵死的：智能体不能自己给自己立规矩。

### 需求5 · 表述更正

任务详情 5W 区：

- 「谁建的」：`source=human` → **用户**；智能体分发 → 显示 Bot 名。
- 「来源」：`source=human` → **用户自建**；否则 → 智能体分发。

不再把「`ui`」这种平台伪身份暴露给你看。
